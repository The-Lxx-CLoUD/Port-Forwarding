۱. Cloudflare Tunnel چیست؟

Cloudflare Tunnel (که ابزار خط‌فرمانش cloudflared نام داره) یه راه امن برای اتصال یه سرویس لوکال (سرور وب، API، سرور SSH، هر سرویس TCP دیگه) به اینترنت، از طریق شبکه‌ی Cloudflare‌ـه — بدون اینکه لازم باشه هیچ پورتی روی روتر یا فایروالت باز کنی.

تفاوت اصلیش با چیزی مثل ngrok:

  • می‌تونی روی دامنه‌ی خودت (که DNSـش زیر Cloudflare‌ست) یه ساب‌دامین دائمی و رایگان بسازی
  • تانل به‌صورت یه اتصال «Named Tunnel» با شناسه‌ی ثابت تعریف میشه که هربار همون آدرس رو داره (برخلاف لینک‌های تصادفی)
  • کاملاً رایگانه، حتی برای استفاده‌ی دائمی و پروداکشن سبک
  • می‌تونه هم ترافیک HTTP/HTTPS و هم ترافیک TCP خام رو فوروارد کنه

مثل ngrok، ایجنت cloudflared روی سیستم تو یه اتصال خروجی به سرورهای Cloudflare باز می‌کنه؛ ترافیک ورودی از دامنه‌ی تو، از طریق همون اتصال به سرویس لوکالت می‌رسه.

۲. نصب cloudflared

ویندوز

نصب‌کننده رو از اینجا دانلود کن و اجرا کن:

https://github.com/cloudflare/cloudflared/releases/latest

یا با winget:

winget install --id Cloudflare.cloudflared

مک (macOS)

brew install cloudflared

لینوکس (Debian/Ubuntu)

sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list

sudo apt update && sudo apt install cloudflared

لینوکس (باینری مستقیم — روی هر توزیعی)

curl -L --output cloudflared \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x cloudflared
sudo mv cloudflared /usr/local/bin/

بررسی نصب:

cloudflared --version

۳. روش سریع (Quick Tunnel) — بدون نیاز به دامنه یا لاگین

اگه فقط می‌خوای سریع یه سرویس لوکال رو موقتاً اکسپوز کنی و دامنه یا اکانت Cloudflare نداری، این ساده‌ترین راهه. فرض کن سرویست روی پورت 1080 اجراست: 

cloudflared tunnel --url tcp://localhost:1080

یا برای یه سرور وب روی پورت 3000:

cloudflared tunnel --url http://localhost:3000

خروجی یه لینک تصادفی زیر دامنه‌ی trycloudflare.com بهت میده، مثلاً:

https://random-words-here.trycloudflare.com
این حالت «Quick Tunnel» موقتیه — نیازی به لاگین یا اکانت نداره، ولی هر بار که اجراش کنی یه لینک تصادفی جدید می‌گیری و برای استفاده‌ی طولانی‌مدت یا پروداکشن مناسب نیست. برای آدرس دائمی، بخش‌های بعدی رو دنبال کن.

۴. روش دائمی — لاگین و اتصال به اکانت Cloudflare

برای ساختن یه تانل دائمی با آدرس ثابت، اول باید یه اکانت Cloudflare داشته باشی (رایگانه) و یه دامنه که DNSـش رو به Cloudflare منتقل کرده باشی.

  1. اگه دامنه نداری یا نمی‌خوای دامنه وصل کنی، می‌تونی از همین بخش رد بشی و فقط از Quick Tunnel (بخش ۳) استفاده کنی.
  2. وارد شدن به اکانت از طریق ترمینال:
cloudflared tunnel login

این دستور یه لینک توی مرورگرت باز می‌کنه؛ باید لاگین کنی و یکی از دامنه‌های زیر اکانتت رو انتخاب کنی. بعد از تایید، یه فایل certificate (معمولاً cert.pem) توی ~/.cloudflared/ ذخیره میشه که هویتت رو برای ساخت تانل‌ها تایید می‌کنه.

۵. ساخت یک تانل نام‌دار (Named Tunnel)

بعد از لاگین، یه تانل با یه اسم دلخواه بساز:

cloudflared tunnel create mytunnel

این دستور یه UUID یکتا برای تانلت می‌سازه و یه فایل credentials (<tunnel-id>.json) توی ~/.cloudflared/ ذخیره می‌کنه. برای دیدن لیست تانل‌هایی که ساختی: 

cloudflared tunnel list

۶. اتصال دامنه به تانل (DNS Routing)

حالا یه ساب‌دامین از دامنه‌ات رو به این تانل وصل کن:

cloudflared tunnel route dns mytunnel proxy.yourdomain.com

این دستور خودکار یه رکورد CNAME توی DNS دامنه‌ات (که روی Cloudflare مدیریت میشه) می‌سازه که به تانلت اشاره می‌کنه. از این به بعد، proxy.yourdomain.com همیشه به همین تانل وصل میشه — دائمی و ثابت.

۷. فایل کانفیگ config.yml و قوانین Ingress

یه فایل کانفیگ بساز (معمولاً توی ~/.cloudflared/config.yml) که مشخص می‌کنه هر ساب‌دامین به کدوم سرویس لوکال فوروارد بشه: 

tunnel: mytunnel
credentials-file: /home/user/.cloudflared/<tunnel-id>.json

ingress:
  - hostname: proxy.yourdomain.com
    service: tcp://localhost:1080
  - hostname: app.yourdomain.com
    service: http://localhost:3000
  - service: http_status:404

نکات مهم درباره‌ی ingress:

  • هر hostname باید قبلاً با دستور بخش ۶ به این تانل route شده باشه
  • می‌تونی چند سرویس مختلف (یکی TCP، یکی HTTP) رو زیر یه تانل واحد تعریف کنی
  • قانون آخر همیشه باید یه catch-all بدون hostname باشه (معمولاً http_status:404) — این قانون الزامیه و باید آخرین آیتم لیست باشه

۸. اجرای تانل و اجرا به‌صورت سرویس دائمی

برای اجرای دستی تانل با فایل کانفیگی که ساختی:

cloudflared tunnel run mytunnel

اگه فایل کانفیگت جای دیگه‌ایه یا اسم دیگه‌ای داره، مسیرشو صریح بده: 

cloudflared tunnel --config /path/to/config.yml run mytunnel

اجرا به‌صورت سرویس سیستمی (تا با ری‌استارت سیستم هم روشن بمونه)

روی لینوکس (systemd):

sudo cloudflared service install
sudo systemctl start cloudflared
sudo systemctl enable cloudflared

روی ویندوز:

cloudflared service install

این دستورات cloudflared رو به‌عنوان یه سرویس پس‌زمینه نصب می‌کنن که خودکار با کانفیگ پیش‌فرضت اجرا میشه.

۹. تانل TCP خام (برای SSH یا سوکت اختصاصی)

همون‌طور که توی بخش ۷ دیدی، با گذاشتن service: tcp://localhost:PORT توی ingress، می‌تونی هر سرویس TCP دلخواه (نه فقط HTTP) رو فوروارد کنی — مثلاً همون اسکریپت کلاینت/سروری که پورت 1080 داشت، یا یه سرور SSH.

سمت کلاینت (کسی که می‌خواد به این سرویس وصل بشه)، برای دسترسی از طریق Cloudflare باید از ابزار cloudflared access استفاده کنه که یه پروکسی TCP لوکال می‌سازه:

cloudflared access tcp --hostname proxy.yourdomain.com --url localhost:1080

این دستور یه پورت لوکال (1080) روی سیستم کلاینت باز می‌کنه که هر ترافیکش رو از طریق Cloudflare به سمت سرور اصلی تونل می‌کنه. یعنی توی اسکریپت کلاینتت کافیه به localhost:1080 وصل بشی؛ خود cloudflared access بقیه‌ی مسیر رو مدیریت می‌کنه.

برای تانل‌های TCP خصوصی (غیر عمومی)، معمولاً از Cloudflare Access و پالیسی‌های احراز هویت هم استفاده میشه تا فقط کاربرهای مجاز بتونن وصل بشن — این بخش پیشرفته‌تره و توی داشبورد Cloudflare Zero Trust قابل تنظیمه.

۱۱. نکات امنیتی

  • فایل‌های cert.pem و <tunnel-id>.json رو هیچوقت جایی به اشتراک نذار — این‌ها هویت تانل و اکانتت رو تایید می‌کنن.
  • برای سرویس‌های حساس، از Cloudflare Access (احراز هویت قبل از رسیدن ترافیک به سرویس لوکالت) استفاده کن، نه فقط یه تانل باز عمومی.
  • فقط پورت‌هایی که واقعاً لازمه رو توی ingress تعریف کن — سرویس‌های اضافه رو اکسپوز نکن.
  • وقتی کارت تموم شد، تانل رو متوقف کن یا اگه سرویس دائمی نصب کردی، در صورت نیاز systemctl stop cloudflared بزن.
هر hostname که توی ingress تعریف و route می‌کنی، تا وقتی تانل روشنه، از هرجای اینترنت قابل دسترسیه (مگر اینکه پشتش Cloudflare Access یا پالیسی احراز هویت بذاری). سرویس‌های بدون پسورد یا با تنظیمات پیش‌فرض رو این‌طوری اکسپوز نکن.
